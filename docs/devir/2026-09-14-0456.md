## Hatalar, kök nedenler ve doğrulama

1. **Çevirinin otomatik yeniden denemesi bazen erken bitiyordu.** Gerçek genel testte üç deneme yerine iki deneme görüldü. `setTimeout` geri çağrısı duvar saatindeki `retryAt` değerinden önce çalışınca zamanlayıcı siliniyor, `updatePlayhead` işi henüz zamanı gelmediği için dışlıyor, `whenIdle` erken çözülüyordu. Kalan süre için yeniden zamanlayıcı kuruluyor. Kontrollü saat testinde 10 ms hedefi için 9 ms'de uyanma, sonra ikinci denemede 30 ms yerine 29 ms'de uyanma üretildi: eski kod `0 !== 1` ile başarısız; düzeltmeden sonra üç deneme ve terminal durum doğru. Backoff ve deneme sınırı gevşetilmedi.
2. **Korpus hash hatası:** Git'teki LF dosyaları Windows checkout sırasında CRLF olmuştu. Manifest ve konuşma içeriği değiştirilmedi. `.gitattributes` korpus için LF zorunlu kılıyor. Mevcut çalışma kopyası da buna uyarlandı; 6 fixture/12 cue hash ve provenance kontrolü geçti. Korpus dosyalarının Git içeriklerinde değişiklik yok.
3. **Python subprocess PID zaman aşımı:** testin venv bulunmadığında başlattığı `python`, Windows Store takma adıydı. Gerçek yorumlayıcıdan `sys.executable` sorgulayan ortak keşif eklendi. Gerçek parent/child iptal testi geçti; süreç ağacı 144,149 ms'de kapandı ve yetim süreç bırakmadı.
4. **Başlangıç testindeki zaman varsayımı:** ayar yükleme IIFE'si bir `initialSettingsReady` Promise'ına bağlandı; Electron testi sabit 1,2 saniye yerine tamamlanmayı bekliyor. Ayar IPC yanıtı 2,5 saniye geciktirilerek başlangıç ve 60 seek kontrolü doğrulandı. Ürün başlangıcının çalışma sırası değiştirilmedi; test artık yükleme hızı varsaymıyor.
5. **Sohbetin eksik girdi hatası yanlış bağımlılık hatasıyla maskeleniyordu:** API anahtarı, veri dosyası ve boş soru doğrulaması `openai` importundan önce yapılır. Eksik anahtar/boş soru testleri paket olmadan doğru hatayı veriyor; geçerli istekte paket gereksinimi devam ediyor.

## Kullanım ve yeni test seçenekleri

Kullanıcıya yeni ayar eklenmedi. Mevcut çeviri işlemi, erken zamanlayıcı uyanmasında denemeyi kaybetmeden devam eder.

- `WHISPER_TEST_PYTHON`: testlerde kullanılacak gerçek Python yürütülebilir dosyası. Yoksa yerel venv, Windows `py` launcher ve diğer Python komutları denenir. Üretim ortamının desteklenen Python 3.10/3.11 gereksinimi değişmedi.
- `VIDEO_E2E_OUT`: her Electron denemesine ayrı rapor klasörü.
- `VIDEO_E2E_STRESS=1`: ilk çift dil yüklemesinden sonra 60 ileri/geri seek.
- `VIDEO_E2E_SETTINGS_DELAY=2500`: yalnız testte `settings:load` IPC yanıtına 2,5 saniye gecikme.

## Genel paket ve açık engeller

`npm test` iki kez çalıştırıldı. İlkinde 6 dosya başarısızdı; bunun içindeki yeni yakalanan retry yarışı düzeltildi. Son koşuda **5 dosya başarısız**:

| Test | Kanıtlanan engel |
| --- | --- |
| `browser-stream-fixtures.test.js` | Localhost bağlantısı ECONNREFUSED. |
| `backend/test_export_anki.py` | `genanki` kurulu değil. |
| `backend/test_ffmpeg_integration.py` | ffmpeg bulunamıyor. |
| `backend/test_transcribe.py` | Sistem Python'unda `numpy` ve kurulu `faster-whisper` kontrolü dahil 10 hata. |
| `backend/test_ytdlp_update.py` | Localhost HTTP bağlantıları engelleniyor. |

NumPy içeren, önceden hazır gelen Python 3.12 çalışma zamanı ile `backend/test_transcribe.py` ayrıca çalıştırıldı: **177 geçen, 1 başarısız** (`faster-whisper` kurulum kontrolü). Bu test, desteklenen üretim venv'inin kurulmuş olduğu anlamına gelmez. NumPy bağımlı kodların ayrıca doğrulanmasıdır.

Soket deneyi `127.0.0.1`, `::1` ve IPv4 tüm arayüz bağlamasında yerel bağlantının reddedildiğini doğruladı. Salt okunur güvenlik duvarı incelemesinde `codex_sandbox_offline_block_loopback_tcp` kuralı görüldü. Güvenlik kuralı kaldırılmadı veya başka kanaldan aşılmadı. Kullanıcıdan desteklenen ortam izinleriyle localhost erişiminin açılması istendi; henüz yanıt/ortam değişikliği yok.

Python 3.11 Windows kurucusu için [resmî indirme kaynağı](https://www.python.org/downloads/release/python-3119/) kontrol edildi. `curl.exe` indirmesi `getaddrinfo() thread failed to start` ile başarısız oldu; kurucu çalıştırılmadı. Bu tek hata indirme sorununun kesin ağ kök nedenini kanıtlamaz. GitHub Git erişimi çalışıyor.
