# Git bağlantı hatasının Proxifier ile ilişkisi

- Repo: https://github.com/dorukakindev/whisper-browser ; dal: `master`.
- Başlangıç HEAD: `bb206e6495b7a442fb35a42efe7233759bc4643e`; çalışma ağacı temiz.
- Başlangıç ve bitiş ürün kodu aynı: `6e7e420b262e0b4027ac475feaf63f8fb0a85bbc`. Ürün kodu değişmedi.

Kullanıcı Proxifier'ın bağlantı hatasına neden olup olmadığını sordu ve kısa süreli kapatarak kontrol etmeyi onayladı. Proxifier açıkken Git ve Windows curl `getaddrinfo() thread failed to start` hatası veriyordu. Aynı sırada Windows TCP 443 kontrolü ve Node DNS çözümlemesi başarılıydı; curl'e DNS ile alınan IP `--resolve` üzerinden verilince GitHub HTTP 200 döndürüyordu.

Proxifier için CloseMainWindow false döndü; süreç kullanıcı izni kapsamında Stop-Process ile kapatıldı. Çalışan Proxifier sayısı sıfır olduğunda, normal `git ls-remote origin refs/heads/master` başarılı oldu ve Windows curl ek DNS parametresi olmadan HTTP 200 aldı. Bu karşılaştırma Proxifier etkinliğinin önceki Git/curl hatasını tetiklediğini gösteriyor. Hangi Proxifier DNS kuralının veya bağlantı müdahalesinin kök mekanizma olduğu ayrıca belirlenmedi; ayarlar değiştirilmedi.

Proxifier kapalıyken `git push origin master` başarılı: bekleyen kurulum notu, dört browser geliştirmesi ve devir notu GitHub'a gönderildi. Yerel HEAD ve uzak master `bb206e6495b7a442fb35a42efe7233759bc4643e` olarak eşleşti. Önceki notlardaki push engeli bu gönderim için kalktı; tarihsel kayıtlar değiştirilmedi.

Bu teşhis notu ve DEVIR-NOTU.md indeksi ayrı dokümantasyon commit'iyle gönderilir. Test sonunda Proxifier aynı çalıştırıcıdan yeniden açılır; son durum teslim mesajında bildirilir. Profil veya proxy kimlik bilgileri okunmadı/yayımlanmadı, güvenlik duvarı değiştirilmedi. Yeni bağımlılık veya şema yok. Ürün testleri bu ağ teşhisinde çalıştırılmadı. Sonraki adım gerekirse Proxifier'da Git/curl için uygun kuralları ayrı bir görevde incelemektir; kalıcı ayar düzeltmesi yapıldığı iddia edilmez.
