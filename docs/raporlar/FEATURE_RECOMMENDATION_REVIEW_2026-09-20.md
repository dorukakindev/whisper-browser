## Source corrections to the proposal pool

1. **TTML/DFXP and static DASH templates are not missing as described in BP-04 and the September 14 research.** `src/browser-subtitles.js` implements XML timing/paragraph/span handling and `parseMp4Stpp`; `src/browser-dash-capture.js` consumes static segment matchers, and `tests/browser-dash-capture.test.js` includes static/dynamic, repetition and multi-period cases. Further work should be driven by a failing real structural fixture, not a second parser.
2. **Page full-text search is present, but page *semantic* search is a different proposal.** `src/watch-index.js` has page FTS; `backend/browser_media_tools.py` and `src/browser-media-tools.js` currently search subtitle cues semantically. The persistent semantic worker reported for P79-04 removes one dependency/latency objection to BP-05, but page-embedding capture, retention, query UI and privacy behavior are new work.
3. **Local preview has reusable machinery, not a ready player wire.** `src/browser-reference-media.js:58` extracts a still; `src/browser-feature-services.js:183-216` ties it to a chosen reference file in an active browser tab. `src/renderer/renderer.js` has a text-only `seekTip` for the local player and a separate `player.localPath`. BP-02 therefore needs an authorized local-player media identity/IPC path as well as hover UI, cancellation and cache limits. Do not promise an 80-line UI-only patch.
4. **SmartTube already has search debounce, source switching, a watch-library view with progress and an Up Next recommendation rail** (`src/renderer/renderer.js:22907-23008`, `23071+`, `14059+`, `23708+`). It does **not** thereby have a user-managed play queue or progress bars on SmartTube cards. R75's generic “history missing” means a SmartTube history section, not absence of stored watch history. `browserYoutubeHideShorts` and YouTube page CSS already exist, so a new global Hide Shorts implementation would duplicate them; filtering SmartTube results is a separate small option.
5. **Invidious subtitles `tlang` is not an established free-quality replacement for model translation.** `backend/invidious.py:361+` selects/downloads source captions; `src/browser-subtitles.js:1505` only identifies an already service-translated URL. Treat `tlang` as a user-labelled, opt-in comparison/fallback if a real fixture proves support and cue alignment, not automatic default Turkish translation.
6. **The Great Courses/Netflix/Hulu adapters remain evidence-gated.** The September 14 report itself says those services were not tested end-to-end. Later Great Courses CEA/HLS work makes its original gap description stale. No protected-stream circumvention or guessed CDN URLs should be planned.
7. **R76's “small” platform items are not all small.** Browser tab lifecycle freezing, per-partition incognito/proxy, userscript GM network privileges, LAN remote server and automatic updates cross lifecycle/security/distribution boundaries. Each needs an independent spike and acceptance test.

## What to build, in order

| Priority | Candidate | Why it fits now | Acceptance gate before claiming done |
| --- | --- | --- | --- |
| 1 | **SmartTube continuity: card progress + local History/Continue Watching, then a separate user-managed Play Next queue/context action** | Existing watch-library and recommendation rail can be reused; makes the new player useful without depending on a live third-party account. | Video-ID mapping, no duplicate cards, resume across restart, queue survives/clears predictably, card/context keyboard behavior, `ended`/manual-next race and failed-probe recovery. Deliver progress/history first; queue second. |
| 2 | **Preview while seeking, as two bounded paths:** local-file stills and Invidious storyboard tiles | High-visibility playback improvement; existing text `seekTip` and reference thumbnail code provide pieces. [Invidious' API](https://docs.invidious.io/api/) documents `storyboards` metadata on videos. | No privileged arbitrary path from renderer; generation-cancel on scrub/media switch; bounded decode/cache; absent/failed storyboard falls back to time/cue text; local and YouTube paths measured separately. |
| 3 | **Local channel subscriptions with explicit import/export** | Signed-in Invidious feeds currently require a session (`src/main.js:1429-1436`); a local list offers a reliable, privacy-preserving fallback. [Invidious channel endpoints](https://docs.invidious.io/api/channels_endpoint/) expose latest videos, but instance availability varies. | Channel-ID dedupe, export→import round trip, pagination/partial failure, request budget and stale refresh status. Do not claim YouTube account subscriptions are synchronized. |
| 4 | **Targeted subtitle discovery: local moviehash matching, plus real-fixture-driven service acquisition** | Directly advances the core subtitle use case. `src/browser-subtitle-search.js` lacks moviehash, while current generalized HLS/DASH/CEA acquisition already handles some cases. | File-hash read bounded and authorized; wrong-edition results ranked below exact match; no upload of local media; for each service use consented structural fixtures and verify first/last expected segment, cue coverage, period/offset and translation alignment. No live account/DRM bypass claim. |
| 5 | **Small playback/UX follow-ups:** MediaSession transport/metadata, SmartTube search suggestions, optional card watched/Shorts filter | Low coupling once continuity is correct. [Invidious' API](https://docs.invidious.io/api/) documents search suggestions. | External suggestion requests opt-in or visibly disclosed, debounce/stale-result guards, media buttons target only active playback, OS metadata clears on close/switch, two-language UI. |

The order above is a proposed **sequence**, not authorization to implement all of it in one change. Before each item: inspect current code again, write a failing behavioral test, implement narrowly, run targeted plus project checks and a real UI smoke where applicable. No new dependency is approved by this review.

## Defer or reject by family (covers R75/R76 and the seven blueprints)

| Family | Decision | Reason / trigger to revisit |
| --- | --- | --- |
| YouTube.js authenticated account sync, Piped failover, DeArrow, RYD badge/voting, comment replies, channel tabs/playlist UI | **Defer.** | R75 has valid patterns, but third-party availability/privacy/OAuth and maintenance exceed the current playback-continuity gap. Piped only if measured Invidious outages materially block the app; replies/tabs only after core navigation works. No automatic votes or uploads. |
| BP-01 tab freezing, incognito/container/proxy, SSB, session sync | **Defer.** | Existing unload/hibernation lifecycle is already complex. Frozen-state CDP behavior must be measured in the packaged Electron build against capture, media, DevTools and restore; it is not a drop-in replacement. Containers/proxy can break SSO/DRM. |
| BP-03 GM_* userscripts, Chrome extensions, pre-navigation injection | **Defer; security design first.** | General arbitrary scripts and `GM_xmlhttpRequest` introduce a new privilege boundary. A limited, local, audited script format can be considered when a real missing site adaptation warrants it; no broad CORS bypass. Full Chrome-extension compatibility is not a goal. |
| BP-05 semantic page history | **Conditional later.** | Page FTS is already available. Require a keyword-miss retrieval corpus, user privacy/retention switch, model size/startup cost and local-only evidence before adding embeddings. |
| BP-06 cast / BP-07 LAN phone remote / DLNA | **Probe/defer.** | [Remote Playback](https://www.w3.org/TR/remote-playback/) describes a UA-controlled facility, not proof Electron ships a usable Cast service. Test availability with a local unprotected file first. LAN server would need explicit enablement, binding, pairing and threat model. |
| OpenSubtitles multi-provider subprocess, intro detection, ASS/IMSC renderer replacement, OCR/alignment engines, TTS/denoise | **Defer to measured format/use-case failures.** | Moviehash is the narrow first step. Existing SDH/ASS/TTML/Whisper paths should not be replaced on a generic feature catalogue. Avoid reviving archived Piper as a default dependency. |
| Generic browser polish: PDF, QR, DDG bangs, markdown copy, auto-PiP, focus mode, sleep timer, tab context menu, element picker, read-later, visual polish report | **Backlog, batch by workflow.** | Some are small, but none outranks missing playback continuity/subtitle evidence. Recheck each against current code when selected; prefer a single coherent UX pass rather than many tiny settings. |
| Full browser platform: fingerprint spoofing, tracking-learning matrix, password vault, cookie rewriting, torrent/aria2, tab recording, network proxy/Tor, untrusted remote script catalogs | **Reject for current product scope.** | Expands security/privacy and support burden, often risks streaming compatibility. A verified user problem can reopen a narrow proposal. |
| Direct code copy from FreeTube/NewPipe/ClearURLs etc. | **Reject without license review.** | Architectural patterns are useful; third-party source and data licensing differ. [FreeTube's repo](https://github.com/FreeTubeApp/FreeTube) states AGPL-3.0. SmartTube's [relicensing discussion](https://github.com/yuliskov/SmartTube/issues/5376) is not a blanket permission to copy every historic contribution. |
